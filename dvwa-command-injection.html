PROJECT WRITE-UP / WEB SECURITY

DVWA Command Injection Lab

A controlled lab exercise focused on understanding how unsafe operating-system command handling can create serious security risk.

← Back to projects

Objective

Understand how user-controlled input can reach operating-system commands in a deliberately vulnerable application and identify defensive controls that prevent it.

Lab Approach

  • Reviewed how the application handled network utility input.
  • Observed differences in filtering across DVWA security levels.
  • Compared how separators and validation rules changed request behavior.
  • Focused on why direct command execution with user input is unsafe.

What I Learned

The lab showed that blacklisting a few characters is fragile. Secure designs avoid shell execution where possible and strictly control allowed input.

Mitigation

  • Avoid passing user input to shell commands.
  • Use safe APIs instead of invoking a shell.
  • Apply strict allow-list validation.
  • Run services with least privilege.
This write-up documents practice performed only in an intentionally vulnerable or authorized lab environment.
