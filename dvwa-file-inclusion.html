PROJECT WRITE-UP / WEB SECURITY

DVWA File Inclusion Lab

A hands-on lab comparing file inclusion behavior and input validation controls across security levels.

← Back to projects

Objective

Understand how applications become vulnerable when file paths are built directly from user-controlled parameters.

Lab Approach

  • Reviewed the page/file parameter used by the DVWA module.
  • Compared path handling and filtering at different security levels.
  • Observed the limitations of blacklist-based controls.
  • Documented safer design patterns for file selection.

What I Learned

File inclusion risk increases when applications trust arbitrary path input. Mapping user choices to fixed server-side file identifiers is much safer.

Mitigation

  • Use allow-listed file identifiers rather than raw paths.
  • Normalize and validate paths.
  • Prevent traversal outside approved directories.
  • Disable unnecessary remote inclusion features.
This write-up documents practice performed only in an intentionally vulnerable or authorized lab environment.
