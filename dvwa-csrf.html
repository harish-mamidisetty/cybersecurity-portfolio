PROJECT WRITE-UP / WEB SECURITY

DVWA CSRF Lab

A hands-on DVWA exercise comparing CSRF defenses such as origin/referer checks and anti-CSRF tokens.

← Back to projects

Objective

Understand how a browser can send authenticated requests on behalf of a logged-in user and how applications verify that sensitive actions are intentional.

Lab Approach

  • Observed state-changing requests in the DVWA CSRF module.
  • Compared behavior when request-origin checks were present.
  • Reviewed the use of per-request or per-session anti-CSRF tokens.
  • Documented why token validation is stronger than relying only on headers.

What I Learned

CSRF protection depends on proving user intent for sensitive actions. Tokens, SameSite cookies and origin validation work best as layered defenses.

Mitigation

  • Use unpredictable anti-CSRF tokens.
  • Set appropriate SameSite cookie attributes.
  • Validate Origin/Referer where suitable.
  • Require re-authentication for highly sensitive actions.
This write-up documents practice performed only in an intentionally vulnerable or authorized lab environment.
